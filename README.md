# MALUNA — телеграм-бот бренда

Бот даёт короткую паузу среди дня: предсказание, ритуал под настроение, астропрогноз на 2027 год и справочник по продуктам и практикам.

Бот **не хранит персональные данные**: ни имени, ни даты рождения, ни переписки. Он никогда не пишет первым — только отвечает на нажатие кнопки.

> ## ⚠️ Обязательный шаг: бот должен быть админом канала
>
> Бот работает **только для подписчиков `@maluna118`** — проверка стоит на входе, до всех разделов. Чтобы она заработала, **добавь бота администратором в канал**; прав по умолчанию достаточно.
>
> Пока этого нет, `getChatMember` возвращает ошибку, и бот **пропускает всех подряд**. Так сделано намеренно: запирать бот целиком из-за сетевого сбоя или неверной настройки хуже, чем на время пустить лишних.
>
> Проверить, работает ли шлюз:
> ```bash
> docker compose logs bot | grep subscription_check_failed
> ```
> Пусто — проверка работает. Есть строки — бот ещё не админ канала.

## Что внутри

| Раздел | Что делает |
|---|---|
| 🕯 Предсказание | Одна светлая фраза в сутки, сброс в 00:00 по Москве. Повторное нажатие в тот же день показывает ту же карточку. |
| ✨ Собери свой ритуал | Пять вопросов, на выходе ритуал под время, настроение и то, что есть дома. |
| 🔮 Астропрогноз 2027 | Спрашивает день и месяц рождения и сразу забывает их. |
| 🎁 Подарок за отзыв | Человек присылает фото отзыва и получает нумерологический прогноз на 2027 год по дате рождения. |
| 📖 Справочник | Как пользоваться продуктами, практики со свечами, утилизация. |
| 💜 О бренде | Пара слов и ссылка на сайт. |

Команды: `/start` — начать заново, `/delete` — стереть все свои данные, `/reload` — перечитать контент и `/reviews` — посмотреть присланные отзывы (обе только для админов).

## Подарок за отзыв

Человек присылает фото или скриншот своего отзыва и получает персональный нумерологический прогноз на 2027 год.

**Подлинность отзыва не проверяется** — засчитывается любая присланная картинка. Так задумано: смысл в том, чтобы людям было легко, а отзывы ты отсматриваешь сам.

**Фото просим один раз.** Прислал — доступ открыт навсегда, при следующем заходе бот сразу спрашивает дату.

### Как посмотреть отзывы

Отправь боту `/reviews` — придут последние десять картинок с датой и номером аккаунта отправителя. Команда работает только для тех, кто указан в `ADMIN_IDS`; остальным бот на неё не отвечает вовсе.

Все файлы лежат на сервере в `data/reviews/` с именами вида `2027-01-15_424242_1.jpg` — дата, номер аккаунта, порядковый номер. В репозиторий они не попадают.

### Как считается цифра

Складываются все цифры дня, месяца и 2027, пока не останется одна:

```
15 июня → 1+5+0+6+2+0+2+7 = 23 → 2+3 = 5 → «5 — год перемен»
```

Тексты девяти разборов лежат в `content/numerology_2027.yaml`. Править можно `title` и `text`, поле `number` трогать нельзя — по нему бот находит нужный разбор.

**Дата рождения не сохраняется.** Из неё считается цифра, после чего дата выбрасывается — как и в астропрогнозе. В базу попадает только цифра от 1 до 9.

## Как добавить предсказание

Самая частая задача. Программировать не нужно.

1. Открой файл `content/cards.yaml` в любом текстовом редакторе.
2. Скопируй последний блок целиком и вставь в конец файла:

```yaml
- id: card_009
  title: "Тёплый день"
  text: "Сегодня всё сложится мягче, чем ты ждёшь ✨"
  tags: []
  active: true
```

3. Поменяй три вещи:
   - `id` — новый номер, такого не должно быть больше нигде в файле;
   - `title` — заголовок в 2–4 слова;
   - `text` — одна-две строки.
4. Сохрани файл и отправь боту команду `/reload`.

**Тон.** Предсказание — это подарок, а не утешение. Обращение на «ты», без имени, максимум один-два эмодзи из 🕯 ✨ 💜.

> Хорошо: «Вселенная приготовила тебе удивительный день ✨»
> Плохо: «Сегодня спокойный день. Не торопись» — звучит как сочувствие.

**Гендерная нейтральность.** Текст должен одинаково читаться любым человеком, поэтому в карточках нет «сделала», «устал», «готова», «сама», «рада». Опора на настоящее и будущее время и на повелительное наклонение: «Сегодня всё складывается», «Загляни внутрь».

**Запретные темы:** здоровье, политика, деньги, отношения, внешность и вес, утраты, работа и увольнения.

Всё это проверяется автоматически:

```bash
pytest tests/test_cards_quality.py
```

Тест падает и показывает, в какой карточке что не так — например, «card_012: слово „рада“». Заодно ловит одинаковые тексты и заголовки.

В файле 365 карточек — год без повторов.

## Как обновить каталог товаров

Каталог не правится руками — он собирается из выгрузки с сайта.

1. Обнови файл `content/KATALOG_MALUNA.md` и папку `content/images/`.
2. Запусти:

```bash
python scripts/import_catalog.py
```

3. Отправь боту `/reload`.

Скрипт разложит товары по `content/products.yaml`, а картинки переведёт из `.webp` в `.jpg` и сложит в `content/media/` — Telegram надёжно показывает именно JPEG.

### Кнопка «Купить на сайте»

Под карточкой товара и под астропрогнозом бот показывает кнопку, которая ведёт на страницу товара. Ссылки берутся из колонки «Страница» в выгрузке каталога.

**Цены в бота не попадают** — их показывает сайт. Скрипт выбрасывает строку «Цена», и отдельный тест следит, чтобы цифры не просочились обратно в описания.

Подпись кнопки задаётся в `content/texts.yaml` → `guide` → `buy_button`. Поставишь там пустую строку `""` — кнопка исчезнет сразу отовсюду:

```yaml
guide:
  buy_button: ""     # кнопки покупки больше нет
```

### Если правишь `products.yaml` вручную

Так тоже можно, но при следующем импорте правки потеряются. Поля:

| Поле | Обязательно | Что писать |
|---|---|---|
| `id` | да | Латиницей без пробелов, например `mono_basil`. Ни у кого не повторяется. |
| `name` | да | Название как на упаковке. |
| `group` | нет | Верхний уровень меню, например `candles`. Пусто — товар сразу в первом меню. |
| `category` | да | Второй уровень: `cosmetics`, `astro_candles`, `mono_set`… |
| `short_desc` | да | Одна строка: что это. |
| `description` | нет | Полное описание из каталога. |
| `how_to_use` | нет | Шаги, каждый с новой строки после дефиса. |
| `care` | нет | Как хранить. |
| `disposal` | нет | Как утилизировать. |
| `photos` | нет | Пути к картинкам от папки `content`. В карточке показывается первая. |
| `url` | нет | Страница товара на сайте. Из неё делается кнопка «Купить». Пусто — кнопки нет. |
| `active` | нет | `false` прячет товар, не удаляя его. |

**Меню строится само.** Появилась новая `group` или `category` — в справочнике появился новый пункт. Чтобы у него была красивая подпись, добавь строку в `content/texts.yaml` → `guide.groups` или `guide.categories`, например `soap: "Мыло"`. Без этого в меню покажется сам код.

## Как пополнить базу ритуалов

Сейчас база живёт в `content/MALUNA_rituals3.md` — 176 ритуалов. Импорт понимает и markdown, и Excel.

**Из markdown-файла:**

1. Дописывай строки в сводную таблицу и блоки `### N. Название` ниже — связка по номеру.
2. Запусти:

```bash
python scripts/import_rituals.py content/MALUNA_rituals3.md
```

**Из таблицы Excel:**

1. Открой `MALUNA_rituals.xlsx` в Excel или Numbers, лист **«Ритуалы»**.
2. Дописывай строки. Значения в колонках «Время суток», «Настроение» и «Нужные продукты» пиши **через запятую**.
3. Сохрани в `.xlsx` и запусти `python scripts/import_rituals.py`.

В обоих случаях в конце — команда `/reload` боту.

> Скрипт **перезаписывает** `content/rituals.yaml` целиком, поэтому веди базу в чём-то одном. Собрать таблицу из текущего yaml: `python scripts/import_rituals.py --template`

**Что можно писать в колонках** — только эти значения, иначе импорт откажется работать и покажет номер строки:

| Колонка | Допустимые значения |
|---|---|
| Время суток | `утро`, `день`, `вечер`, `любое` |
| Время (мин) | `5`, `15`, `30` |
| Настроение | `устала`, `тревожно`, `хочется вдохновения`, `радостно`, `любое` |
| Что хочется | `отдохнуть`, `взбодриться`, `позаботиться о коже`, `создать уют` |
| Нужные продукты | `свечи MALUNA`, `гидрофильное масло MALUNA`, `очищающий гель MALUNA`, `увлажняющий крем MALUNA`, `душ`, `ванна`, `кофе`, `чай` |
| Активен | пусто или `да` — показывать, `нет` — спрятать |

**Как бот выбирает ритуал.** Сначала отсекает всё, что не совпало по «Что хочется», и всё, что длиннее доступного времени. Потом считает баллы: по одному за совпавшее время суток, за каждое совпавшее настроение и за каждый продукт, который человек отметил дома. Выигрывает набравший больше.

Сейчас в базе есть строка на каждую комбинацию первых четырёх ответов, поэтому подбор всегда попадает точно — проверено перебором всех 144 сочетаний. Плюс 32 ритуала на случай, когда дома есть ровно один предмет.

Если будешь чистить базу, проследи, чтобы для каждого из четырёх «Что хочется» остался хотя бы один **пятиминутный** ритуал — иначе человек с пятью минутами останется без ответа.

## Остальные контент-файлы

Все лежат в папке `content/`, все правятся так же: сохранил → `/reload`.

| Файл | Что в нём |
|---|---|
| `texts.yaml` | Все фразы бота и подписи кнопок. Приветствие, ошибки, заголовки. |
| `cards.yaml` | Предсказания. |
| `rituals.yaml` | База для конструктора ритуала (собирается из Excel). |
| `products.yaml` | Каталог продуктов для справочника. |
| `astro_2027.yaml` | 12 текстов астропрогноза по знакам. |
| `practices.yaml` | Практики со свечами. |
| `faq.yaml` | Инструкция по свечам и способы утилизации. |
| `replies.yaml` | Что отвечать, если человек пишет текстом, а не кнопками. |
| `_source/` | Оригиналы документов Pages, из которых собран контент. Бот их не читает. |

**Правила для всех файлов:**

- отступы делаются **пробелами**, не табами;
- длинный текст пишется после знака `|` с отступом;
- `{фигурные скобки}` — это подстановки, их нельзя переименовывать и удалять;
- `active: false` прячет запись от пользователей, не удаляя текст.

### Если бот не запустился после правки

Значит, в файле опечатка. Проверь, что не так, не запуская бота:

```bash
python scripts/validate_content.py
```

Скрипт покажет имя файла, номер записи и поле, например:
`cards.yaml: item 'card_009' — field title: Field required`

То же сообщение придёт админу в ответ на `/reload`. Пока контент битый, бот продолжает работать на прежней версии — на пользователях это не отражается.

## Запуск на своём компьютере

Нужен Python 3.11 или новее.

```bash
# 1. Виртуальное окружение и зависимости
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Настройки
cp .env.example .env
# открой .env и впиши BOT_TOKEN от @BotFather и свой ADMIN_IDS

# 3. Запуск
python -m bot.main
```

Проверить, что бот жив: открой http://localhost:8080/health — должен ответить `{"status": "ok", ...}`.

### Переменные в `.env`

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather). Обязательно. |
| `ADMIN_IDS` | Кому доступна `/reload`, через запятую. Свой номер узнаешь у [@userinfobot](https://t.me/userinfobot). |
| `CHANNEL_USERNAME` | Канал для проверки подписки, по умолчанию `@maluna118`. |
| `CHANNEL_URL` | Ссылка на канал для кнопки «Подписаться». |
| `DB_PATH` | Где лежит база, по умолчанию `data/maluna.db`. |
| `HEALTH_PORT` | Порт health-check, по умолчанию `8080`. |
| `LOG_LEVEL` | `INFO` обычно, `DEBUG` при отладке. |
| `REDIS_URL` | Необязательно. Без него состояние диалогов живёт в памяти — для одного бота этого достаточно. |

> **Важно про астропрогноз.** Чтобы бот мог проверять подписку, добавь его администратором в канал `@maluna118` (достаточно прав по умолчанию). Если этого не сделать, раздел не сломается: он откроется всем, а в логи попадёт предупреждение.

## Запуск в Docker

Так бот запускается и на своём компьютере, и на сервере — команды одинаковые. Python ставить не нужно, всё уедет внутрь контейнера.

### Шаг 1. Получить токен

Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя и адрес бота. В ответ придёт строка вида `8123456789:AAH...` — это токен, он даёт полный доступ к боту, никому его не показывай.

Там же у [@userinfobot](https://t.me/userinfobot) узнай свой числовой `id` — он понадобится для `/reload`.

### Шаг 2. Заполнить `.env`

```bash
cp .env.example .env
```

Открой `.env` и поменяй две строки:

```
BOT_TOKEN=8123456789:AAH...      # токен от @BotFather
ADMIN_IDS=123456789              # твой id, можно несколько через запятую
```

Остальное можно не трогать. Файл `.env` в репозиторий не попадает — он в `.gitignore`.

### Шаг 3. Запустить

```bash
docker compose up -d --build
```

Первая сборка занимает пару минут, дальше — секунды.

### Шаг 4. Проверить

```bash
docker compose ps               # STATUS должен быть Up ... (healthy)
docker compose logs -f bot      # логи, выйти по Ctrl+C
curl localhost:8080/health      # {"status": "ok", ...}
```

Если всё хорошо, открой бота в Telegram и напиши `/start`.

### Повседневные команды

```bash
docker compose logs -f bot        # смотреть логи
docker compose restart bot        # перезапустить
docker compose down               # остановить
docker compose up -d --build      # применить изменения в коде
```

**Контент менять пересборкой не нужно.** Папки `data/` и `content/` подключены томами: правишь файл в `content/` на компьютере → отправляешь боту `/reload` → изменения на месте. База в `data/maluna.db` переживает и перезапуск, и пересборку.

### Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| `Не удалось запустить бота: Telegram не принял токен` | Опечатка в `BOT_TOKEN`. Скопируй токен из @BotFather целиком, вместе с частью до двоеточия. |
| `Не удалось запустить бота: cards.yaml: ...` | Ошибка в контент-файле, в сообщении указано где. Проверь: `python scripts/validate_content.py` |
| `env file .env not found` | Не сделан шаг 2: `cp .env.example .env` |
| `port is already allocated` | Порт 8080 занят другой программой. Поменяй `HEALTH_PORT` в `.env` на свободный, например `8090`, и перезапусти. |
| `Cannot connect to the Docker daemon` | Не запущен Docker Desktop. Открой его и подожди, пока значок кита перестанет мигать. |
| Контейнер перезапускается по кругу | `docker compose logs --tail=20 bot` — причина в последних строках. |

Бот работает через long polling, поэтому ни домен, ни SSL-сертификат, ни настройка вебхуков не нужны.

### Доступ по подписке

Бот открывается только подписчикам `@maluna118`. Проверка стоит на входе и действует на всё сразу — до разделов неподписанный не доходит.

Что работает **без** подписки, намеренно:

- **`/delete`** — человек должен иметь возможность стереть свои данные, даже если отписался от канала;
- **команды админов** из `ADMIN_IDS`, иначе `/reload` и `/reviews` стали бы недоступны.

Результат проверки кешируется на 10 минут: столько отписавшийся ещё сохраняет доступ. Сменить можно в `CACHE_TTL_SECONDS` в [bot/services/subscription.py](bot/services/subscription.py).

И ещё раз о главном: **пока бот не админ канала, шлюз пропускает всех** — см. предупреждение в начале файла.

## Что бот хранит

В базе четыре таблицы и ничего лишнего:

```
users              user_id, когда пришёл, когда был последний раз
user_card_history  какое предсказание показали в какой день
events             обезличенная статистика: какие разделы открывают
review_photos      ссылки на фото отзывов, сами файлы в data/reviews/
```

Чего в базе **нет**: имени, даты рождения, контактов, текста сообщений. Дата рождения — и в астропрогнозе, и в подарке за отзыв — живёт несколько миллисекунд, ровно чтобы вычислить знак или цифру года, и не попадает ни в базу, ни в логи. Ответы на вопросы ритуала лежат в оперативной памяти и стираются, когда человек уходит в меню.

**Единственное исключение — фото отзывов.** Их бот сохраняет, и на скриншоте обычно видно имя и аватарку человека. Поэтому перед отправкой бот честно предупреждает, что фото сохраняется, а `/delete` удаляет его вместе со всем остальным — и строку в базе, и файл с диска.

Команда `/delete` спрашивает подтверждение и предупреждает, что действие необратимо.

Структура:

```
bot/

  content/           схемы, загрузчик yaml/json, кеш в памяти
  db/                миграции и три таблицы
  services/          предсказание, подбор ритуала, знак зодиака, подписка
  handlers/          экраны бота
  keyboards/         inline-клавиатуры и схема callback_data
  middlewares/       перехват ошибок
content/             контент-файлы (см. выше)
scripts/             импорт ритуалов, проверка контента
migrations/          схема базы
tests/               тесты, включая сквозные сценарии с поддельным Telegram
```

Что стоит знать, если будешь править код:

- **русских строк в коде нет** — весь интерфейс живёт в `content/texts.yaml`, это проверяется тестом;
- **контент валидируется схемами** `bot/content/schemas.py`; словари допустимых значений там же, менять их можно только вместе с вопросами в `texts.yaml`;
- **проактивных отправок нет и быть не должно** — ни планировщика, ни рассылок, ни напоминаний;
- **в логи не попадают** текст сообщений и дата рождения; за этим следит фильтр в `bot/logging_setup.py`;
- **в `events.payload_json` нельзя писать персональные данные** — репозиторий бросает исключение, если попытаться.
